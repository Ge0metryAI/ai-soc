# 结构化提示词(Prompt 模板)

> 本项目中复用且高效的提示词模板。要点:**给角色、给上下文、给约束、给输出格式**,而非一句话甩需求。

## 1. 选题决策
```
你是资深工程师。这是竞赛题目 PDF(N 选一)。请从【难度 / 后端复杂度 / 功能检查项数量 /
能否部署到 Vercel / 与团队业务契合度】五个维度横向评估每个题,
输出对比表 + 推荐一个"既好做又能完全满足要求"的题,并说明理由与风险。
```

## 2. 技术方案
```
针对【题目 D · AI SOC 看板】产出完整技术方案,必须包含:
① Mermaid 架构图 ② TypeScript 数据模型 ③ 页面/路由拆解
④ 核心算法伪代码(置信度/优先级/聚合/建议/误报学习)
⑤ Vercel 部署方案 ⑥ 功能检查清单逐项对照。
约束:纯前端可实现、Vercel 可部署、零基础友好。
```

## 3. 方案评审(对抗式)
```
作为挑剔的评审,对照竞赛 PDF 原文逐条审查这份方案:
哪些已满足、哪些是盲点、哪些理解有偏差。
要求:诚实、给出严重度,不要客套。对我不认同的点请反驳并给依据。
```

## 4. 破坏性变更框架适配
```
项目 AGENTS.md 警告"这不是你熟悉的 Next.js"。写任何代码前,
先读 node_modules/next/dist/docs/ 下相关指南(route handler / server-client /
缓存 / 升级说明),确认与你记忆中(Next 14/15)的差异后再动手,避免用过时 API。
```

## 5. 可解释规则引擎
```
作为安全运营专家,设计一个"可解释"的告警置信度评分引擎(纯函数):
输入 = 告警类型 / 资产重要性 / 严重度 / 误报学习调整;
输出 = 0-100 置信度 + breakdown(各项贡献值 + 命中规则文字),供 UI 透明展示。
再据此推导 P0-P3 优先级与处置建议模板。强调"可解释"而非黑盒。
```

## 6. 安全审查
```
对 src/ 全部源码做严格安全审查(只报告不改):重点 SSRF(用户可配的外联端点)、
越权(角色校验是否可绕过)、注入(SQL 是否参数化)、信息泄露。
按 🔴致命/🟡应修/🟢建议 分级,给文件:行 + 具体修复建议。
```

## 7. AI 处置建议(运行时真 LLM)
```
你是资深 SOC 分析师。根据给定告警(名称/类型/源目的IP/严重度/置信度/优先级),
用简体中文输出一条具体、可执行的处置建议(50 字内,含动作与目标对象),
只输出建议本身,不要解释或前缀。
```
> (#7 即 `/api/ai-suggest` 中实际下发给模型的 system prompt。)
