# 对 Vibe Coding 的理解(心得)



## 一句话
**Vibe Coding 不是"让 AI 替我写代码",而是"我负责方向与判断,AI 负责构建与调试"——人始终是决策者,AI 是高效执行者。**

## AI 擅长什么(放手交给它)
- **脚手架与样板**:建项目、配 shadcn、写 CRUD、API Routes、Zustand store——又快又准。
- **确定性逻辑**:可解释规则引擎(置信度/优先级/聚合/误报学习)这类"规则明确"的纯函数,AI 一次成型。
- **调试与适配**:build 报错、类型错误、读框架源码确认 API、修边界条件,AI 定位快。

## AI 不擅长什么(必须人把关)
- **破坏性变更/新版本**:训练数据里是 Next 15,实际是 Next 16,凭记忆写会踩坑——必须"先读文档再写"。
- **安全**:引入"用户自配外联端点"功能时,AI 顺手就埋了 SSRF;是人提醒"有漏洞就要修"才闭环。安全需要人主动施压。
- **产品判断 / UX 可见性**:降噪功能"做了但看不见",是人体验后才发现——AI 容易"完成功能"却忽略"用户能否感知"。
- **方向选择**:选哪个题、要不要上 Turso、AI 定位成"可解释规则引擎"还是"假装真 AI"——这些价值判断只能人来拍。

## 人的判断在哪里起了关键作用
1. **Vercel 约束**:一句"还要能部署在 Vercel 上吗"直接否决了本地 SQLite,逼出 Turso + 降级的双层架构。
2. **持久化决策**:在"省事 localStorage"与"合规真数据库"之间,综合评审与题目原文,选定 Turso。
3. **诚实定位**:把"规则模拟"亮明为"可解释规则引擎",而非假装真 AI——反而成了卖点。
4. **漏洞必修**:坚持修掉 AI 功能引入的 SSRF,并要求实测验证。

## 最大体会
高效 Vibe Coding 的关键,是**把人的精力从"敲代码"转移到"提出清晰的问题、设定正确的约束、做关键的判断、验证 AI 的产出"**。AI 把执行成本降到近乎为零,于是**方向是否正确、约束是否到位、验证是否充分**,成了决定成败的真正变量。
